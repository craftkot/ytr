# Operator: Reality

Адаптивный наблюдатель для Minecraft Java 26.3 + Fabric.

**Текущая версия:** 0.4.0  
**Рабочая ветка:** operator-dev  
**Репозиторий:** https://github.com/craftkot/ytr

## Что умеет 0.4.0

- Первые 24 000 игровых тиков мира — пассивное наблюдение.
- Отдельная память игроков по UUID; офлайн-время не засчитывается.
- Запись маршрутов и пройденной дистанции.
- Учёт добычи камня, руды и других природных блоков.
- Карта выкопанных блоков в виде 3D-координатных ячеек.
- Восстановление связных участков по соседству граней (6 направлений).
- Предварительная классификация участков: линейный тоннель, камера, неправильная форма или маленький участок.
- Приближённая горизонтальная центральная линия тоннелей с помощью Zhang-Suen thinning.
- Сжатие центральной линии в граф: тупики, узлы-развилки, сегменты коридоров и циклы.
- Координаты обнаруженных развилок, примерные начальные/конечные координаты основных сегментов и границы крупнейших участков.
- Отдельный анализ текущего измерения.
- Ограничение карты последними 4 096 ячейками на игрока.
- Атомарное сохранение памяти и миграция старых сохранений на схему 3.

## Ограничения сетевой карты

Граф 0.4 строится по горизонтальной проекции X/Z. Вертикальные слои схлопываются в одну колонку. Поэтому шахты, расположенные одна над другой, могут визуально объединиться, а длина центральной линии является оценкой, а не точной длиной прохода. Это топологическая модель для горизонтальных тоннелей, а не полноценный трёхмерный скелет.

Карта строится только из подходящих блоков, сломанных игроком после установки мода. Уже существующие пустоты и старые шахты не сканируются. Обычная установка блока игроком в записанную ячейку проверяется через один серверный тик и удаляется из карты. Взрывы, поршни, потоки жидкостей и изменения от других модов пока не отслеживаются.

**Оператор не изменяет мир:** автоматическое копание, установка блоков и перестройка шахт отключены.

## Сборка

Требования: Minecraft Java 26.3, Java 25, Fabric Loader 0.20.1+, Fabric API 0.165.2+26.3 и Gradle 9.8.2.

В корне проекта:

    gradle clean test build

Запуск тестового клиента:

    gradle runClient

Готовые JAR-файлы появятся в build/libs/.

## Команды

    /operator status
    /operator profile
    /operator tunnels
    /operator network

- status — фаза мирового наблюдения, число профилей и число сохранённых ячеек.
- profile — персональная статистика игрока.
- tunnels — связные 3D-участки выкопанных блоков в текущем измерении.
- network — горизонтальная центральная линия и граф тоннелей: тупики, развилки, сегменты и циклы.

Команды profile, tunnels и network нужно выполнять от имени игрока.

## Где хранятся данные

    <папка мира>/operator_reality/operator-memory.json

Схема 3 хранит ограниченную карту выкопанных ячеек. Сохранения 0.1/0.2/0.3 нормализуются при загрузке; существующие профили не должны сбрасываться.

## Тестирование модели без Minecraft

В PowerShell:

    New-Item -ItemType Directory -Force build/model-test | Out-Null
    javac -Xlint:all -Werror -d build/model-test src/main/java/ru/ehtid/operator/data/PlayerMemory.java src/main/java/ru/ehtid/operator/analysis/TunnelAnalyzer.java src/main/java/ru/ehtid/operator/analysis/TunnelNetworkAnalyzer.java tools/OperatorModelSmokeTest.java
    java -ea -cp build/model-test OperatorModelSmokeTest

Полные JUnit-тесты запускаются через gradle test. GitHub Actions дополнительно запускает dedicated server, проверяет /operator status, сохранение мира и корректную остановку.

Перед тестированием на важном мире сделайте резервную копию.
