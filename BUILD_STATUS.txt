Implemented in 0.14:
- Persistent hash-chained recovery audit checkpoints bound to exact PREPARED journal SHA-256.
- Atomic per-journal checkpoint storage, 128-event and 1 MiB size limits.
- /operator transaction prepare: create initial checkpoint #0 after journal is saved.
- /operator transaction audit: save result and list bounded source + neighbor hazard counts.
- /operator transaction checkpoint: verify persisted audit after server restart.
- Read-only MinecraftRecoveryWorldView; cannot be used as a world-mutating adapter.
- RecoveryBoundaryInspector: one-block halo, maximum 8192 neighbor samples, unloaded chunks skipped.
- RelocationHazardAnalyzer: redstone, fluid, gravity, attachments, modded/unknown blocks and block entities.
- Abstract RecoveryExecutor before/after write callbacks and fault-injected retry tests.
- Tests for checkpoint persistence with real temporary files, JSON restart, tampering, bounds and source binding.

Not implemented:
- No direct block writes in Minecraft, no actual house movement or live-world restore.
- No authenticated execution phase or automatic restart recovery.
- No inventory-safe BlockEntity NBT relocation, entity displacement or physics/redstone replay.
- An audit matching the expected AFTER state does not prove Operator performed that change.
