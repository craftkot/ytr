Prepared journal persistence:
- JSON temp file is forced with FileChannel.force(true) before rename.
- Atomic move is used where supported; same-directory fallback otherwise.
- Parent directory fsync is best effort because Windows/filesystem support varies.
- Execution WAL already uses the same file force + atomic replacement + directory fsync strategy.

Known limits:
- Hardware power loss, kernel crash, storage controller volatile cache loss and
  filesystem corruption are not established by normal CI.
- Directory fsync can be unsupported.
- WAL, PREPARED journal and Anvil region files are separate files, not one atomic transaction.
- Block entities/inventories, entities, liquids, redstone, modded blocks, arbitrary
  states and autonomous world mutation remain unsupported.

Sandbox remains experimental, manual and operator-only.
