0.16 changes:
- Manual sandbox apply now uses SandboxTransactionEngine, the same pure-Java
  core as end-to-end crash/fault-injection tests.
- Sandbox rollback now uses the same core for WAL phase transitions and
  RecoveryExecutor world compare-and-restore calls.
- Fail closed before first world write unless the full source/target AABB
  matches its BEFORE preimages and the target region is recorded air.
- Every mutation must have a durable WAL intent before a CAS world change,
  and a confirmed ACK after it. Postcheck validates the entire world.
- COMMITTED phase cannot be reached before all intended write ACKs.
- Regression test for hollow 26-block house full apply/rollback.
- Fault-injection tests for WAL creation error, ACK crash after world write,
  intermediate rollback interruption, retry, unknown edits, wrong offsets,
  occupied destination, write CAS failure.
- Excluded axis-bearing deepslate; 10 simple vanilla block IDs remain.

SAFETY:
- OP-only manual sandbox function, 128-cell per-region maximum.
- No BlockEntity NBT, inventories, non-default states, liquids,
  power/attached/gravity blocks, modded blocks or entities in the AABB.
- No scheduled automatic AI world rewrites.
- WAL and Minecraft chunk disk persistence are not one atomic transaction.
- Existing CI tests DO NOT perform live-world sandbox apply/rollback.
- GitHub workflow artifact labels may still say 0.14.0; the actual 0.16.0
  JAR version must be checked inside the archive.
